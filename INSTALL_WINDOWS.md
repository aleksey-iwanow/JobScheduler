# JobScheduler для Windows 10/11 x64 — инструкция к первому выпуску

Инструкция к JobScheduler 0.1.0. Скачивайте установщик только из [официальных Releases](https://github.com/aleksey-iwanow/JobScheduler/releases). Установщик не имеет цифровой подписи издателя; контрольная сумма опубликована рядом с загрузкой.

## Установка и первый вход

1. Запустите `JobScheduler-0.1.0-win-x64-Setup.exe` на компьютере Windows 10/11 x64, где будут выполняться задачи. Установщик запросит подтверждение администратора Windows, чтобы зарегистрировать фоновую службу, защитить данные и настроить брандмауэр.
2. Подтвердите предупреждение: служба и одобренные задачи на компьютере запускаются от `LocalSystem` с максимальными правами Windows. Предоставляйте роли operator/admin только доверенным людям.
3. При новой установке создайте главного администратора JobScheduler: логин от 3 до 64 символов латиницей, цифрами, точкой, подчёркиванием или дефисом; пароль от 12 до 256 символов.
4. При желании включите значок JobScheduler в области уведомлений при входе в Windows. Служба запускается автоматически при загрузке компьютера независимо от входа пользователя.

Веб-интерфейс и задачи на самом компьютере продолжают работать после выхода из Windows, пока компьютер включён. Задачи запускаются с правами `LocalSystem`, а не от вошедшего в Windows пользователя; им могут быть недоступны его рабочий стол, сетевые диски и личные папки. Контейнерные задачи требуют Docker Desktop отдельно; их работу без входа в Windows первый выпуск не гарантирует.

Издатель JobScheduler распространяет один установщик, но не предоставляет общий сервер. Установите его на Windows-компьютер, где будут работать задачи; остальные пользователи смогут входить через браузер в зависимости от выбранного режима доступа. Учётные записи, процессы и история этой установки хранятся на этом компьютере, а не на сервере издателя. По вопросам работы программы можно написать на `mailggkk@gmail.com`; по вопросам учётной записи и данных конкретной установки обращайтесь к её администратору. Если вы открываете доступ другим людям, сами предоставьте им необходимые сведения об обработке их данных вне интерфейса JobScheduler.

## Доступ к интерфейсу

Администратор выбирает режим в «Настройки → Доступ по сети». Затем администратор Windows на самом компьютере выбирает в значке приложения «Применить настройки и перезапустить» и подтверждает запрос Windows. Закрытие значка не останавливает службу.

- «Только этот компьютер»: `http://127.0.0.1:8080`, доступ с других устройств закрыт.
- «Локальная сеть»: HTTPS по выбранному локальному IP. Можно добавить доменное имя, направленное на этот IP. Caddy выдаёт локальный сертификат; на каждом клиентском устройстве необходимо доверить его корневому сертификату. Администратор JobScheduler скачивает публичный `.crt` в сетевых настройках после включения режима. Передавайте на другие устройства только этот файл, не закрытый ключ. Само наличие домена не устраняет этот шаг. Добавляйте такой корневой сертификат только на доверенные устройства: он даёт этому экземпляру право выпускать сертификаты, которым эти устройства будут доверять.
- «Интернет»: нужен принадлежащий вам публичный домен, DNS-запись на внешний IP и доступный снаружи TCP-порт 443. Если компьютер за роутером, настройте переадресацию 443 на него. Caddy получает публичный сертификат через проверку на порту 443.

При смене режима Windows попросит подтвердить настройку правила брандмауэра и перезапуск службы. Для локальной сети правило ограничено частным сетевым профилем и локальной подсетью; для интернета открывается входящий TCP 443 только для Caddy. Сохранённая, но не подтверждённая в Windows смена режима не вступит в силу даже после перезагрузки компьютера. В режиме локальной сети убедитесь, что Windows помечает вашу домашнюю сеть как «Частная».

Не открывайте порты 5090 и 3000 наружу: API и веб-интерфейс слушают только `127.0.0.1`, входящие подключения принимает Caddy.

## Обновление и удаление

Для обновления сначала выберите «Закрыть значок» в области уведомлений, затем запустите установщик новой версии на том же компьютере с подтверждением администратора Windows. Закрытие значка не останавливает службу. Установщик остановит службу, создаст резервную копию SQLite и запустит службу снова. База, настройки и ключи находятся вне папки программы — в `%PROGRAMDATA%\JobScheduler` — и сохраняются при обновлении.

Удаление программы останавливает и удаляет службу и правило брандмауэра, но оставляет процессы, историю и учётные записи в `%PROGRAMDATA%\JobScheduler`. Если вы хотите удалить и данные, сначала сделайте нужную резервную копию, затем удалите этот каталог вручную с правами администратора Windows.

Если предыдущая установка прервалась или программа удалена, но папка данных осталась, мастер предложит выбор:

- «Восстановить прежнюю базу» — введите логин и пароль существующего администратора. Мастер проверит их, создаст резервную копию базы и продолжит установку. Если пароль не подходит или базы нет, прежние данные останутся на месте.
- «Создать новую базу и нового администратора» — мастер переименует всю прежнюю папку `%PROGRAMDATA%\JobScheduler` в `%PROGRAMDATA%\JobScheduler-backup-ГГГГММДД-ЧЧММСС` (при совпадении добавит номер), затем создаст отдельную пустую базу. Прежние данные не удаляются и автоматически в новую базу не переносятся. Для восстановления старых данных сохраните резервную папку и обратитесь к инструкции восстановления.

Эти сценарии пока не проверены на отдельной чистой Windows.

Пока нет автоматического обновления. Новые версии будут выпускаться отдельными установщиками после проверки владельцем проекта.
